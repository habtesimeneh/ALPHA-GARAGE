Comprehensive Solution & Core Modules

The Alpha Garage Management Platform encompasses seven interconnected enterprise modules designed to run seamlessly in real-time across workshop floor tablets, desktop terminals, and mobile devices.

1. Vehicle Intake & Service Desk Module 01
Comprehensive digital check-in capturing VIN, plate number, make, model, year, odometer, fuel level gauge, and pre-existing vehicle body scratches. Generates barcoded customer intake receipts and notifies assigned workshop teams.
2. Job Card & Repair Lifecycle Module 02
State-machine driven workflow: Draft → Diagnosed → In Progress → QC Inspection → Ready → Delivered. Mechanics log labor duration, diagnostic DTC error codes, and replacement parts directly into digital cards.
3. Double-Entry Parts Inventory Module 03
Full supply chain control with SKU, OEM part numbers, shelf/bin tracking, unit costs, retail markup, and supplier catalogs. Automatically locks and deducts stock when assigned to repair jobs, with automated reorder alerts.
4. Billing, Invoices & Tax Engine Module 04
Compliant with Ethiopian tax laws. Computes parts cost, labor cost, and applies 15% Ethiopian Value Added Tax (VAT). Invoices maintain strict financial invariance: immutable receipt generation upon confirmed payment settlement.
5. Manual Payment Verification Module 05
Dedicated verification queue for 22 Ethiopian commercial banks and 4 mobile wallets. Prevents duplicate transaction IDs, enforces high-resolution slip streaming outside public web root, and permits 1-click approvals.
6. VIP Client Portal & Video Gallery Module 06
Customer self-service portal for live service tracking, appointment bookings, estimate sign-offs, and payment submission. Includes an educational video gallery showcasing workshop standards and maintenance best practices.

End-to-End Operational Lifecycle Workflow

[CUSTOMER INTAKE] → Reception registers Vehicle (VIN, Plate, Odometer) → Intake Inspection ↓ [JOB CARD CREATION] → Service Advisor assigns Master Mechanic & Priority Level ↓ [DIAGNOSTICS & REQUISITION] → Mechanic diagnoses fault → Requisitions Parts from Inventory ↓ [INVENTORY ALLOCATION] → Inventory Manager approves parts → Atomic Stock Deduction ↓ [REPAIR & QUALITY CONTROL] → Mechanical Execution → Foreman QC Road Test Inspection ↓ [INVOICING & PAYMENT] → Invoice generated (Parts + Labor + 15% VAT) → Customer Pays (Bank/Telebirr) ↓ [ACCOUNTANT VERIFICATION] → Slip verification in Queue → Immutable Receipt → Vehicle Release

Security & Permission Enforcement Architecture

Multi-Layer Access Governance
Every HTTP route executes require_login() followed by require_permission('permission_name') before reading inputs or querying database records. Direct URL manipulation by unauthorized users triggers an automatic security event logged into the immutable SHA-256 audit chain.
Front-Office / Floor Separation
Mechanics cannot view financial profitability or invoice balances; Cashiers and Accountants cannot modify technical diagnostic findings or delete job cards.
Customer Identity Isolation
Customer portal accounts are strictly scoped to the authenticated customer's owned vehicles and invoices, preventing IDOR (Insecure Direct Object Reference).

4-Stage Idempotent Verification Workflow

[STEP 1: CUSTOMER SUBMISSION] Customer selects Bank/Telebirr → Enters Reference Number & Amount → Uploads Slip (JPG/PNG/PDF) Collision check prevents duplicate reference numbers on the same provider. ↓ [STEP 2: CENTRALIZED VERIFICATION QUEUE] Submission appears in Accountant's live queue with KPI indicators (Pending, Under Review). High-resolution proof viewer displays slip with pan/zoom and anti-IDOR security. ↓ [STEP 3: HUMAN AUDIT & RECONCILIATION] Accountant cross-references transaction reference against garage's online bank statement. Action options: [APPROVE] or [REJECT WITH REASON]. ↓ [STEP 4: FINANCIAL COMMITMENT (ATOMIC)] Approved: Creates immutable Payment Record → Deducts Invoice Balance → Triggers SMS/Email. Rejected: Invoice balance remains untouched → Customer notified to re-submit valid proof.
Financial Invariance Guarantee: Pending or rejected payment submissions never reduce invoice balances. Balances are adjusted solely upon explicit accountant approval through PaymentService::record(), protected by database-level triggers against post-settlement modification.

Technical Architecture & Security Hardening

Alpha Garage is built upon a high-performance, framework-independent architecture designed for maximum operational longevity, zero third-party licensing dependencies, and bulletproof security.

Technology Stack Specification

Architectural Layer Technology Component Specification & Architectural Justification
Core Engine PHP 8.2+ Native MVC Zero-framework overhead; sub-50ms server response times; type safety with declare(strict_types=1).
Database Management MySQL 8.0 / MariaDB InnoDB engine, utf8mb4_unicode_ci encoding, foreign key constraints, integer-cent arithmetic for ETB.
Frontend & UI HTML5 / Modern CSS3 / ES6 Lightweight custom styling; zero node/npm runtime bloat; high performance on low-bandwidth mobile connections.
Cryptographic Audit SHA-256 Hash Chaining Tamper-evident append-only ledger for all security events, logins, payment updates, and deletions.
Web Server & Runtime Apache 2.4 / Nginx Strict .htaccess directory shielding preventing direct access to app/, storage/, and database/.

Security Hardening & Defense-in-Depth Matrix

1. Anti-CSRF & XSS Defense
Cryptographic CSRF token validated on every single POST request before routing. All HTML output sanitized through custom e() escaping helper. Strict Content Security Policy (CSP) headers applied.
2. SQL Injection Neutralization
100% of database queries execute via PDO prepared statements with strict parameter binding. Dynamic queries use whitelist-validated columns and fixed structure strings.
3. Secure File Upload Pipeline
Payment slips and vehicle inspection photos are validated using binary magic bytes (MIME verification), renamed with random UUIDs, and stored outside the public document root.
4. Tamper-Evident Audit Logging
Every administrative action, financial transaction, and login event is recorded with prior-hash chaining. Database triggers block record alteration or historical deletion.
